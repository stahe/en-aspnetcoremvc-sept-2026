    3. The Action Model

    An action requires information sent by the browser: the parameters from URL ([?nom=martin&age=42]), form fields, and route parameters. The source course refers to all of this information as the action model. This chapter shows how [ASP.NET Core] provides this information to the action, converts it to the correct type, and validates it. This process is called model binding ([model binding]).

    using Microsoft.AspNetCore.Mvc;

namespace Exemple07.Controllers;

[Route("parametres")]
public class ParametresController : Controller
{
     // /settings/action01?name=martin: the parameter [nom] from URL -> the parameter [nom] from the action
    [HttpGet("action01")]
    public string Action01(string? nom)
    {
        return $"nom = [{nom}], de type {nom?.GetType().Name ?? "null"}";
    }

     // /parameters/action02?age=42: the value is CONVERTIE in the parameter type
    [HttpGet("action02")]
    public string Action02(int age)
    {
        return $"age = [{age}], de type {age.GetType().Name}, ModelState.IsValid = {ModelState.IsValid}";
    }

     // /parameters/action03?age=42: "int?" distinguishes a missing (null) parameter from a zero
    [HttpGet("action03")]
    public string Action03(int? age)
    {
        return $"age = [{age?.ToString() ?? "null"}], ModelState.IsValid = {ModelState.IsValid}";
    }

     // /parameters/action04?page=2: a default value if the parameter is missing
    [HttpGet("action04")]
    public string Action04(int page = 1)
    {
        return $"page = [{page}]";
    }

     // /parameters/action05?q=nest: [FromQuery(Name = ...)] when the names differ
    [HttpGet("action05")]
    public string Action05([FromQuery(Name = "q")] string? recherche)
    {
        return $"recherche = [{recherche}]";
    }

     // /parameters/action06?name=martin&age=42: all parameters at once
    [HttpGet("action06")]
    public Dictionary<string, string> Action06()
    {
        return Request.Query.ToDictionary(p => p.Key, p => p.Value.ToString());
    }
}

    Let’s break down this code:

    • Lines 10–12: The model binding associates the action’s parameters with the query data by name: the action’s parameter [nom] receives the value of the parameter [nom] from URL (the part following [?], called the query string or [query string]). The type [string?] indicates that the value may be missing; in that case, it is [null]. [nom?.GetType().Name ?? "null"]: the name of the value type, or the string ["null"] if the value is [null] (the operator [??] provides a replacement value);
    • lines 17–19: the parameter is declared as type [int]: the template binding converts the received string (["42"]) to a number. If the conversion fails ([?age=abc]), the action is still executed, using the type’s default value (0 for a [int]), and the failure is logged in [ModelState]; the status of the model binding—[ModelState.IsValid]—then becomes [false];
    • lines 24–26: with type [int?] (a “nullable” integer), a missing parameter is represented as [null], not 0: this allows distinguishing between “no age” and “age 0”;
    • lines 31–33: a default value of [C#] replaces a missing parameter;
    • Lines 38–40: The attribute [[FromQuery(Name = "q")]] specifies where to look for the value (in URL) and under what name: The [recherche] parameter of the action receives the [q] parameter from the URL;
    • Lines 45–47: [Request.Query] provides access to all parameters of URL, without any mapping or conversion. [ToDictionary] ([LINQ]) creates a dictionary from it, serialized in JSON.

    The quotation marks around URL are necessary when it contains the character [&], which has a specific meaning for the console. Note that:

    • a parameter is bound by its name, regardless of case ([?NOM=martin] is also valid);
    • its value is converted to the declared type. This is an important difference from [NestJS], where a parameter’s type was merely a declaration ([TypeScript]) that was removed at compile time;
    • an impossible conversion does not cause an error: the action is executed with a default value, and it is up to the action to check [ModelState.IsValid]. A “nullable” type ([int?]) prevents a missing or invalid value from being confused with 0.

    Accented characters and spaces are encoded in a URL ([%C3%A9] for [é], etc.): [ASP.NET Core] decodes them before binding.

    using System.ComponentModel.DataAnnotations;

namespace Exemple08.Models;

// the action model: a class where each property has its own constraints
public class PersonneModele
{
    [Required(ErrorMessage = "le nom est obligatoire")]
    [StringLength(20, MinimumLength = 2, ErrorMessage = "le nom doit avoir de 2 à 20 caractères")]
    public string? Nom { get; set; }

    [Required(ErrorMessage = "l'âge est obligatoire")]
    [Range(0, 150, ErrorMessage = "l'âge doit être compris entre 0 et 150")]
    public int? Age { get; set; }

    [Required(ErrorMessage = "le titre est obligatoire")]
    [AllowedValues("Mr", "Mme", "Melle", ErrorMessage = "titre inconnu")]
    public string? Titre { get; set; }

     // optional: no [Required]
    [EmailAddress(ErrorMessage = "adresse électronique invalide")]
    public string? Email { get; set; }
}

    Let’s comment on this code:

    • line 1: the namespace for validation attributes;
    • line 10: each expected parameter is a public property ([{ get; set; }]: it can be read and written). The model binding creates a [PersonneModele] object, then populates each property with the parameter of the same name;
    • lines 8–9: the name is required ([[Required]]) and must be between 2 and 20 characters long ([[StringLength]]). Each attribute accepts a custom error message ([ErrorMessage]). The properties are declared “nullable” ([string?], [int?]): a parameter may be omitted from a query, and [[Required]] enforces this requirement;
    • lines 12–14: age is converted to an integer, which is required and must be between 0 and 150 ([[Range]]);
    • Line 17: The title must be part of a list of values ([[AllowedValues]], introduced with [.NET] 8);
    • Line 21: The email address is optional (no [[Required]]); if included, it must be valid.

    using System.Net;
using Exemple09.Models;
using Microsoft.AspNetCore.Mvc;

namespace Exemple09.Controllers;

// no [ApiController]: the action is TOUJOURS executed, and it is this action that
// determines what to do with an invalid template
[Route("personnes")]
public class PersonnesController : Controller
{
    [HttpGet("action01")]
    public ContentResult Action01(PersonneModele personne)
    {
         // ModelState: the result of the ET model validation
        if (ModelState.IsValid)
        {
            return Page($"<p>Bienvenue {personne.Titre} {personne.Nom} ({personne.Age} ans)</p>");
        }
         // errors, field by field
        var items = ModelState
            .Where(champ => champ.Value!.Errors.Count > 0)
            .Select(champ => $"<li>{champ.Key} : {string.Join(", ", champ.Value!.Errors.Select(e => e.ErrorMessage))}</li>");
        return Page($"<p>Le formulaire contient des erreurs :</p><ul>{string.Join("", items)}</ul>");
    }

     // a page HTML (status code 200 in both cases)
    private ContentResult Page(string html) => Content(html, "text/html; charset=utf-8");
}

    Let’s comment on this code:

    • line 9: without [[ApiController]], the action is always executed, regardless of whether the model is valid or not. A class-type parameter is searched for everywhere: in URL, in form fields, and in the route;
    • line 13: the model binding and validation were performed before the action was executed: the [personne] object is populated, and [ModelState] contains any errors;
    • lines 16–18: no errors: a welcome page;
    • lines 21–23: otherwise, the list of errors. [ModelState] is a dictionary in which each key is the name of a field ([Nom], [Age]...) and each value is the status of that field, along with its list of errors ([Errors]). The methods [LINQ], [Where] (filter), and [Select] (transform) retain the fields with errors and generate one line HTML per field. [!] informs the compiler that a value is not [null];
    • line 24: a page listing the errors;
    • line 28: in both cases, the response is a HTML page, with status code 200.

    using System.ComponentModel.DataAnnotations;

namespace Exemple10.Models;

// IValidatableObject: a validation written in C#, for what the attributes
// cannot express (here: CHAQUE, a list item)
public class ChoixModele : IValidatableObject
{
    private static readonly string[] Couleurs = ["rouge", "vert", "bleu"];

    [MinLength(1, ErrorMessage = "choisissez au moins une couleur")]
    public List<string> Couleur { get; set; } = [];

    public IEnumerable<ValidationResult> Validate(ValidationContext contexte)
    {
        foreach (var couleur in Couleur.Where(c => !Couleurs.Contains(c)))
        {
             // yield return: the method returns errors one by one
            yield return new ValidationResult($"couleur inconnue : {couleur}", [nameof(Couleur)]);
        }
    }
}

    Let’s comment on this code:

    • line 11: [[MinLength(1)]]: the list must have at least one element;
    • lines 14–18: the method [Validate], called by the validation after the attributes, checks each color. It returns an error ([ValidationResult]) for each unknown color, indicating the relevant field. [yield return] returns errors one by one, without creating a list.

    using System.Globalization;
using Microsoft.AspNetCore.Mvc.ModelBinding;

namespace Exemple12.Liaison;

// a "model binder": converts a French date "23/09/2026" to DateOnly
public class DateFrBinder : IModelBinder
{
    public Task BindModelAsync(ModelBindingContext contexte)
    {
         // the raw value, found in URL, the form, the route...
        var brut = contexte.ValueProvider.GetValue(contexte.ModelName).FirstValue;
        if (DateOnly.TryParseExact(brut, "dd/MM/yyyy", CultureInfo.InvariantCulture, DateTimeStyles.None, out var date))
        {
             // success: the value that the action will receive
            contexte.Result = ModelBindingResult.Success(date);
        }
        else
        {
             // failure: an error in ModelState ("02/31/2026" is also rejected)
            contexte.ModelState.AddModelError(contexte.ModelName, $"[{brut}] n'est pas une date jj/mm/aaaa valide");
        }
        return Task.CompletedTask;
    }
}
    • line 7: a model binder implements the [IModelBinder] interface;
    • line 9: its method [BindModelAsync] receives the binding context: the parameter name ([ModelName]), the value sources ([ValueProvider]: URL, the form, the route...), [ModelState]...;
    • line 12: the raw value of the parameter ([FirstValue]: the first one, if there are multiple);
    • lines 13–16: [DateOnly.TryParseExact] converts a string in the [jj/mm/aaaa] format to [DateOnly] (a date without a time), and returns [false] if this is impossible, including for a date that does not exist (02/31/2026). If successful, [ModelBindingResult.Success(date)] provides the value that the action will receive;
    • line 21: if the operation fails, an error is added to [ModelState];
    • line 23: the method is asynchronous by nature ([Task]), but there is nothing to wait for: it returns a task that has already completed.

    using Microsoft.AspNetCore.Mvc.ModelBinding;

namespace Exemple12.Liaison;

// the browser’s preferred language, read from the header
// "Accept-Language: fr-FR,fr;q=0.9,en;q=0.8" -> "fr"
public class LangueBinder : IModelBinder
{
    public Task BindModelAsync(ModelBindingContext contexte)
    {
        var entete = contexte.HttpContext.Request.Headers.AcceptLanguage.ToString();
        var premiere = entete.Split(',')[0].Trim();
        var langue = premiere.Length >= 2 ? premiere[..2].ToLowerInvariant() : "fr";
        contexte.Result = ModelBindingResult.Success(langue);
        return Task.CompletedTask;
    }
}
    • line 11: the [Accept-Language] header, which specifies the user’s preferred languages;
    • lines 12–13: the first two letters of the first language. [premiere[..2]] is a range ([range]): the characters with indices 0 and 1.

        if (!ModelState.IsValid)

    3.6.5. Conclusion

    The action template is constructed by the template binding based on the request: route parameters, URL, form fields, JSON body, and headers. The values are converted to the parameter types and then validated against the attributes. The result of these two steps is stored in [ModelState]. For a server JSON, [[ApiController]] automatically rejects an invalid model; for a HTML application, the action itself tests [ModelState.IsValid] (example 09) so that the form can be redisplayed. This is the subject of the next chapter.
