    1.1. The Role of ASP.NET Core MVC in a Web Application

    A web application is often built in layers, with each layer communicating only with its neighboring layers:

    • the web layer receives requests HTTP from the browser and returns pages HTML to it. This is the layer that [ASP.NET Core MVC] helps us write;
    • The business layer contains the application’s business rules (for example, “a patient can have only one upcoming appointment”). It knows nothing about the web: it could just as easily serve a command-line application;
    • The data access layer (layer [DAO], for [Data Access Object]) reads from and writes to the database. We will use the ORM [Entity Framework Core] ([Object Relational Mapper]), which maps the rows of the tables and objects in [C#].

    The web layer itself follows the [MVC] ([Model – View – Controller]) model:

    • the controller (C) is a class whose methods—called actions—each handle a specific type of request (for example, [GET /agenda]). An action reads the request parameters, invokes the business layer, and then selects the view to display;
    • the model (M) is the set of data that the action passes to the view: a [C#] object;
    • the view (V) is a [Razor] file (extension [.cshtml]): from HTML, in which [C#] expressions—preceded by the character [@]—are replaced by data from the model.

    The processing of a request follows the numbered steps in the diagram:

    • 1: The browser sends a HTTP request, for example, [GET /agenda?idMedecin=1&jour=2026-09-24];
    • 2: The web server [Kestrel], integrated with [ASP.NET Core], receives the request. It passes through a series of middleware components (cookie reading, authentication, static files, etc.), then [ASP.NET Core] selects the action responsible for handling this request: this is routing. Before reaching the action, the request may still pass through filters, which we’ll explore in later chapters;
    • 3: The action requests the data it needs from the business layer;
    • 4: It constructs the view template and designates the view that should display it;
    • 5: The [Razor] view engine renders the HTML page, which [ASP.NET Core] returns to the browser.

    [ASP.NET Core] is the web framework for Microsoft’s [.NET] platform. Free and open-source, it runs on [Windows], [Linux], and [macOS]. It can create servers that return JSON to a [JavaScript] client ([Angular], [React], [Flutter]...) as well as traditional web applications, where the server generates the HTML pages and the browser simply displays them. It is this second use case—the MVC part of the framework—that this document examines. Like [NestJS], which drew heavily on it, [ASP.NET Core] is based on two ideas: attributes ([[HttpGet]], [[Route]], [[Authorize]]...) describe the roles of classes and methods, and dependency injection provides each object with the dependencies it needs.

    1.2. Tools Used

    The examples were written and tested using the following tools (their installation is described in the appendix):

    • SDK [.NET] 10 ([Software Development Kit]), which contains the [C#] compiler, the [ASP.NET Core] framework, and the [dotnet] command-line tool. [.NET] 10 is the current LTS (Long-Term Support) version;
    • the [Visual Studio Code] editor, with the [C# Dev Kit] extension;
    • a recent browser ([Chrome], [Firefox], [Edge]);
    • the command-line tool [curl], which displays the raw HTTP responses (it is included with [Windows] 10 and 11);
    • the SGBD [MySQL] (or [MariaDB]), for example, the one for [Laragon] under [Windows], starting from the chapter on data access, and for the case study.

    The [ASP.NET Core] framework is part of SDK: the examples do not require any additional libraries until Chapter 8. Examples 25 through 28 and the case study use three libraries, which are automatically downloaded from the [nuget.org] website during their first compilation (so you must be connected to the Internet on that day): [Microsoft.AspNetCore.Authentication.JwtBearer] (JWT tokens), [BCrypt.Net-Next] (password hashes), and [Pomelo.EntityFrameworkCore.MySql] ([Entity Framework Core] for [MySQL]).

    Let’s go over this file:

    • line 9: the target version of [.NET]: [.NET] 10;
    • line 11: “nullable” reference types. The compiler distinguishes between a variable of type [string], which must never be assigned the value [null], from a variable of type [string?], which can be set to that value, and issues a warning for any potential error involving [NullReferenceException];
    • Line 13: The most common namespaces ([System], [System.Linq], [System.Threading.Tasks], [Microsoft.AspNetCore.Builder]...) are automatically imported into each file: there is no need to write the corresponding [using] directives.
