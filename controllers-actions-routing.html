    2. Controllers, Actions, Routing

    This chapter examines the path a request takes, from the browser to the action that processes it, and the response that action returns. Views will not be introduced until Chapter 4: here, actions return text or JSON directly.

    // the application’s “builder”: configuration, logging, services...
var builder = WebApplication.CreateBuilder(args);

// we register the services that MVC needs to find and execute the controllers

// the application is built

    Let’s break down this code:

    • Line 2: [WebApplication.CreateBuilder] creates the application’s “constructor.” It reads the configuration (the [appsettings.json] file, environment variables, etc.), sets up logging, and prepares the list of application services, [builder.Services]. The [args] parameter contains the command-line arguments;
    • line 5: the services required by [MVC] to locate the application’s controllers and execute their actions are added to the list;
    • line 8: the application is built. After this line, the list of services can no longer be modified;
    • line 11: the routes declared by the controllers (the attributes [[HttpGet]], [[Route]]..., which we will discuss) are enabled: without this line, no action would ever be called;
    • line 14: starts the [Kestrel] web server and waits for requests until the application is stopped ([Ctrl-C]). Unless otherwise specified, the server listens on port 5000.

    This file contains neither a class nor a method named [Main]: it is a high-level instruction-based program. The [C#] compiler itself wraps these instructions into a method named [Main], which serves as the program’s entry point. Note also the absence of [using] directives: [WebApplication] belongs to the [Microsoft.AspNetCore.Builder] namespace, which is imported automatically (see [ImplicitUsings] in the introduction).

namespace Exemple01.Controllers;

// A controller is a class that inherits from Controller
public class AccueilController : Controller
{
     // An action: the method called for the request GET /
    [HttpGet("/")]
    public string Index()
    {
         // the value returned by the action is the response sent to the browser
        return "Bonjour de la part d'ASP.NET Core MVC !";
    }
}
    • Line 1: the namespace containing the class [Controller] and the attributes of [MVC];
    • line 3: the namespace for the classes in this file. By convention, it includes the project name ([Exemple01]) and the file’s directory ([Controllers]). The form [namespace X;] (without curly braces) applies to the entire file;
    • line 6: A controller is a public class that inherits from the [Controller] class. By convention, its name ends with [Controller]. [ASP.NET Core] automatically finds the application’s controllers—there is no need to declare them;
    • line 9: the [[HttpGet("/")]] attribute associates the [Index] method with [GET /] requests. A method associated in this way with a route is an action. A [C#] attribute is written in square brackets, immediately before what it describes: it adds information to the method, which the framework reads at startup;
    • Line 13: The value returned by the action is the response sent to the browser.

    using Microsoft.AspNetCore.Mvc;

namespace Exemple02.Controllers;

public class AccueilController : Controller
{
     // GET /: a HTML page containing links to the other actions
    [HttpGet("/")]
    public ContentResult Index()
    {
        const string html = """
            <h2>Exemple 02 - le routage</h2>
            <ul>
              <li><a href="/premier">/premier</a></li>
              <li><a href="/premier/action01">/premier/action01</a></li>
              <li><a href="/premier/produits/17">/premier/produits/17</a></li>
              <li><a href="/premier/produits/17/avis/3">/premier/produits/17/avis/3</a></li>
              <li><a href="/premier/fichiers/images/logo.png">/premier/fichiers/images/logo.png</a></li>
              <li><a href="/premier/produits/abc">/premier/produits/abc</a></li>
              <li><a href="/inconnue">/inconnue</a></li>
            </ul>
            """;
         // Content (text, type): a response whose type is selected (in this case, HTML)
        return Content(html, "text/html; charset=utf-8");
    }
}
    • line 9: the action no longer returns a string, but a [ContentResult]: a response whose content and type are specified;
    • lines 11–22: a raw string [C#] ([raw string literal]), delimited by three quotation marks. It can span multiple lines and contain quotation marks without escaping them. Spaces preceding the closing ["""] are removed from each line;
    • line 24: the [Content(texte, type)] method of the [Controller] class generates a [ContentResult]. The [text/html] type instructs the browser to interpret the text as HTML.

    using Microsoft.AspNetCore.Mvc;

namespace Exemple02.Controllers;

// prefix common to all routes in the controller
[Route("premier")]
public class PremierController : Controller
{
     // GET /first
    [HttpGet("")]
    public string Index()
    {
        return "Action [Index] du contrôleur [Premier]";
    }

     // GET /first/action01
    [HttpGet("action01")]
    public string Action01()
    {
        return "Action [Action01] du contrôleur [Premier], requête GET";
    }

     // POST /first/action01: same path, different method HTTP
    [HttpPost("action01")]
    public string Action01Post()
    {
        return "Action [Action01Post] du contrôleur [Premier], requête POST";
    }

     // GET /first/products/17: {id} is a route parameter, ":int" is a constraint
    [HttpGet("produits/{id:int}")]
    public string Produit(int id)
    {
        return $"Produit n° {id}";
    }

     // GET /first/products/17/reviews/3: two route parameters
    [HttpGet("produits/{id:int}/avis/{numero:int}")]
    public string Avis(int id, int numero)
    {
        return $"Avis n° {numero} du produit n° {id}";
    }

     // GET /first/files/... : {**path} accepts any path ending
    [HttpGet("fichiers/{**chemin}")]
    public string Fichier(string chemin)
    {
        return $"Fichier demandé : {chemin}";
    }
}

    Let’s break down this code:

    • line 6: the [[Route("premier")]] attribute, applied to the class, sets the prefix common to all the controller’s routes: its actions handle URL routes that begin with [/premier];
    • lines 10–11: [[HttpGet("")]]: the action [Index] handles [GET /premier]. The URL for an action is the concatenation of the controller prefix and the action path;
    • lines 17–18: The action [Action01] processes [GET /premier/action01];
    • lines 24–25: the same path, but for the POST method: [[HttpPost]] replaces [[HttpGet]]. There are also [[HttpPut]], [[HttpDelete]], [[HttpPatch]]... The name of the method [C#] ([Action01Post]) is arbitrary: only the attributes matter for routing. Furthermore, within the same class, two methods cannot have the same name with the same parameters;
    • Lines 31–32: [{id}] is a route parameter: this segment of URL can take on multiple values. [:int] is a constraint: the segment must be an integer; otherwise, the route does not match. The value of the segment is passed to the action’s parameter of the same name, [id], which has already been converted to [int]: for [/premier/produits/17], [id] is equal to the number 17. This is the template binding ([model binding]), which the next chapter will examine in detail;
    • lines 38–39: two route parameters, passed to two parameters of the action;
    • Lines 44–46: [{**chemin}] is a "catch-all" parameter ([catch-all]): it accepts any ending for URL, including [/].

    using Microsoft.AspNetCore.Mvc;

namespace Exemple03.Controllers;

[Route("reponses")]
public class ReponsesController : Controller
{
     // a string: sent as-is, with the type [text/plain]
    [HttpGet("texte")]
    public string Texte()
    {
        return "<h1>Action [Texte]</h1>";
    }

     // the same string, declared as HTML: the browser interprets it
    [HttpGet("html")]
    public ContentResult Html()
    {
        return Content("<h1>Action [Html]</h1>", "text/html; charset=utf-8");
    }

     // an object: serialized as JSON, with the type [application/json]
    [HttpGet("json")]
    public object Json()
    {
        return new { nom = "Martin", prenom = "Jean", age = 42 };
    }

     // an array: also serialized as JSON
    [HttpGet("tableau")]
    public string[] Tableau()
    {
        return ["Mme", "Melle", "Mr"];
    }

     // IActionResult: the action selects the complete response (code, content)
     // StatusCode(201, ...): status code 201 (Created) instead of 200 (OK)
    [HttpGet("cree")]
    public IActionResult Cree()
    {
        return StatusCode(201, new { message = "ressource créée" });
    }

     // no response: status code 204 (No Content) means “nothing to display”
    [HttpGet("vide")]
    public IActionResult Vide()
    {
        return NoContent();
    }

     // an asynchronous action: ASP.NET is waiting for the task to complete
    [HttpGet("tache")]
    public async Task<object> Tache()
    {
        var debut = DateTime.Now;
        await Task.Delay(500); // a 500-ms wait, without blocking the server
        return new { attente = $"{(DateTime.Now - debut).TotalMilliseconds:0} ms" };
    }

     // an "expected" error: NotFound(...) returns a 404 response
    [HttpGet("introuvable")]
    public IActionResult Introuvable()
    {
        return NotFound(new { message = "Cette ressource n'existe pas" });
    }

     // an "unexpected" error: an unhandled exception returns a 500 response
    [HttpGet("exception")]
    public string Exception()
    {
        throw new InvalidOperationException("Une erreur imprévue");
    }
}

    Let’s break down this code:

    • lines 9–12: a string is sent as-is, with the header [Content-Type: text/plain; charset=utf-8];
    • lines 16–19: the same string, declared as HTML (see Example 02): the browser interprets it;
    • lines 23–26: an object is serialized as JSON, with the header [Content-Type: application/json]. [new { nom = ..., prenom = ... }] creates an object of an anonymous type: a nameless type generated by the compiler, useful for data that is used only once. The property names of JSON are written as “camelCase” (first letter lowercase), following the convention of [JavaScript];
    • lines 30–33: An array is also serialized as JSON. [["Mme", "Melle", "Mr"]] is a collection expression ([C#] 12), which here creates an array of strings;
    • lines 39–41: when the action needs to select the status code, it returns a [IActionResult]: an object that describes the complete response. The methods of the [Controller] class generate many of these: [StatusCode(201, objet)] produces a 201-code response ([Created]) whose content is the object serialized in JSON;
    • lines 46–48: [NoContent()] returns a 204 status code ([No Content]): “no content”;
    • lines 53–57: An action can be asynchronous ([async]): it then returns a task ([Task<T>]), the equivalent of a promise ([JavaScript]), and [ASP.NET Core] waits for the task to complete before responding. [await Task.Delay(500)] waits 500 ms without blocking the server: while waiting, the thread that was executing the action is returned to the server, which can use it to process other requests. This is how all actions that query a database are written;
    • Lines 62–64: An error expected by the program: [NotFound(objet)] returns a 404 response with the content JSON. Similarly, there are [BadRequest(...)] (400), [Unauthorized()] (401), [Forbid()] (403), [Ok(...)] (200)...;
    • Lines 69–71: an unexpected error: the action throws an exception, which it does not handle. [ASP.NET Core] then responds with a 500 error ([Internal Server Error]).

    using Microsoft.AspNetCore.Mvc;

namespace Exemple04.Controllers;

public class RedirectionsController : Controller
{
     // Permanent redirect (301): the page has permanently changed its address
    [HttpGet("ancienne")]
    public IActionResult Ancienne()
    {
        return RedirectPermanent("/nouvelle");
    }

    [HttpGet("nouvelle")]
    public string Nouvelle()
    {
        return "Vous êtes sur la page [nouvelle]";
    }

     // Temporary redirect (302) to a calculated address
    [HttpGet("aller/{destination}")]
    public IActionResult Aller(string destination)
    {
        return Redirect($"/page/{destination}");
    }

     // redirect to a ACTION: ASP.NET generates the URL itself
    [HttpGet("vers-action/{destination}")]
    public IActionResult VersAction(string destination)
    {
        return RedirectToAction(nameof(Page), new { nom = destination });
    }

    [HttpGet("page/{nom}")]
    public string Page(string nom)
    {
        return $"Vous êtes sur la page [{nom}]";
    }

     // redirect to another site
    [HttpGet("documentation")]
    public IActionResult Documentation()
    {
        return Redirect("https://learn.microsoft.com/aspnet/core");
    }
}

    Let’s break down this code:

    • lines 9–11: [RedirectPermanent(url)] generates a permanent redirect (status code 301, [Moved Permanently]): the page’s address has permanently changed. Browsers and search engines can cache the new address;
    • lines 22–24: [Redirect(url)] generates a temporary redirect (status code 302, [Found]), in this case to a calculated address. [$"/page/{destination}"] is an interpolated string: the expression within curly braces is replaced by its value;
    • lines 29–31: [RedirectToAction(action, valeurs)] redirects to an action, not to a URL: [ASP.NET Core] itself generates the URL for the action [Page] based on its route ([page/{nom}]) and the provided values ([nom = destination]). If the action’s path ever changes, the redirection follows suit. [nameof(Page)] returns the method name (["Page"]): a typo would cause a compilation error, which is not the case with a hand-written string;
    • Lines 42–44: You can redirect to another site.

    2.5. Example 05: The Request and Response Objects

    Each request is represented by a [HttpContext] object, which contains the request ([Request]) and the response currently being generated ([Response]). An action accesses it directly through the properties [HttpContext], [Request], and [Response] of the [Controller] class. This is sometimes necessary, and we’ll do it in the case study (to read or set a cookie, for example), but you need to know what you’re doing.

namespace Exemple05.Controllers;

[Route("http")]
public class HttpController : Controller
{
     // the request: method, path, parameters, headers...
    [HttpGet("requete")]
    public object Requete()
    {
        return new
        {
            methode = Request.Method,
            chemin = Request.Path.Value,
            parametres = Request.QueryString.Value,
            navigateur = Request.Headers.UserAgent.ToString(),
            ip = HttpContext.Connection.RemoteIpAddress?.ToString(),
        };
    }

     // the response: we add a header to it, then the action normally returns its value
    [HttpGet("entete")]
    public string Entete()
    {
        Response.Headers["X-Exemple"] = "05-httpcontext";
        return "Réponse avec un entête ajouté";
    }

     // the "handwritten" response: code, type, then the body
    [HttpGet("reponse")]
    public async Task Reponse()
    {
        Response.StatusCode = 200;
        Response.ContentType = "text/plain; charset=utf-8";
        await Response.WriteAsync("Réponse écrite par [Response.WriteAsync]");
    }

     // ERREUR—don’t do this: write the response; PUIS—return a result
    [HttpGet("double")]
    public async Task<IActionResult> Double()
    {
        await Response.WriteAsync("Début de la réponse... ");
         // The response has already been sent: its code and headers can no longer be changed
        return NotFound();
    }
}

    Let’s break down this code:

    • lines 10–18: the request: the HTTP method ([Request.Method]), the path ([Request.Path]), the parameters of URL ([Request.QueryString]), the headers ([Request.Headers]), and, via [HttpContext.Connection], the client’s address (IP). [?.] is the “null conditional” operator: if [RemoteIpAddress] equals [null], the expression evaluates to [null] instead of causing an error;
    • lines 24–27: the action adds a header to the response, then returns its value normally, which [ASP.NET Core] sends. This is the most common use of [Response];
    • lines 32–36: The action writes the response itself—status code, type, then the body—using [Response.WriteAsync]. It does not return anything ([Task], not [Task<T>]);
    • lines 41–45: the mistake to avoid: writing part of the response and then returning a result. Once the first bytes of the body have been sent to the browser, the status code and headers—which were sent before the body—can no longer be changed.

public class ProduitsController : Controller

     // Dependency injection: ASP.NET provides the implementation of IProduitsService
    public ProduitsController(IProduitsService produitsService)
    {
        this.produitsService = produitsService;
    }

    [HttpGet("")]
    public IReadOnlyList<Produit> Liste()
    {
        return produitsService.FindAll();
    }

    [HttpGet("{id:int}")]
    public IActionResult UnProduit(int id)
    {
        var produit = produitsService.FindById(id);
        if (produit is null)
        {
            return NotFound(new { message = $"Produit n° {id} introuvable" });
        }
        return Ok(produit);
    }
}

The implementation could be replaced (with a version that reads a database, or with a test version) without modifying the controller;
    • lines 17–19: the action delegates to the service. The list is serialized using JSON;
    • lines 23–30: [{id:int}] converts the ID; a nonexistent product returns a 404 response. [Ok(objet)] returns a 200 response whose content is the object serialized in JSON. [is null] checks whether a value is null.

    2.6.6. Service Registration

    [ASP.NET Core] can only provide a service if it knows about it: each service is registered in [builder.Services], along with its lifetime. The file [Produits/ProduitsExtensions.cs]:

    namespace Exemple06.Produits;

// an "extension method": it is called as if it were part of
// IServiceCollection (builder.Services.AddProduits()). It groups the
// records from the "products" section of the application.
public static class ProduitsExtensions
{
    public static IServiceCollection AddProduits(this IServiceCollection services)
    {
         // "When a IProduitsService is requested, return a ProduitsService";
         // Singleton: a single instance, shared by all requests
        services.AddSingleton<IProduitsService, ProduitsService>();
        return services;
    }
}
    • line 6: a static class, which contains only static methods;
    • line 8: an extension method. The keyword [this] before the first parameter allows it to be called as if it were part of that parameter’s type: [builder.Services.AddProduits()]. This is how the [ASP.NET Core] libraries add their services ([AddControllers], [AddAuthentication]...), and it is a good way to group records from a specific part of the application;
    • Line 12: “When a class requests a [IProduitsService], provide it with a [ProduitsService].” [Singleton] is the service’s lifetime: a single instance, created on the first request and shared by all requests. There are two other lifetimes: [Scoped] (one instance per request) and HTTP (one new instance for each request). Chapter 6 will revisit this topic;
    • line 13: the method returns the list of services so that calls can be chained together.
