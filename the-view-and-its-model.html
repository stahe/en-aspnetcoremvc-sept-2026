    4. The View and Its Model

    Up to this point, actions have generated their own responses. In a MVC application, this is the role of a view: a file that describes the page HTML, with placeholders for the data passed to it by the action—the view’s template. [ASP.NET Core MVC] uses the [Razor] view engine: A view is a [.cshtml] file, derived from HTML, into which [C#] code is inserted, preceded by the character [@]. [Razor] is part of the framework: there is nothing to install.

            DateTime.Now.ToString("HH:mm:ss"));
        return View(model);
    }

    // View(name, model): the view is chosen by the action
    [HttpGet("hello/{name}")]
    public IActionResult Hello(string name)
    {
        if (name == "unknown")
        {
            Response.StatusCode = 404;
            return View("Unknown", name);
        }
        var model = new PageModel(
            $"Hello {name}",
            "This time, the action designated the view by its name.",
            DateTime.Now.ToString("HH:mm:ss"));
        return View("Index", model);
    }
}

    Let’s comment on this code:

    • Line 6: The controller derives from class [Controller], rather than [ControllerBase]: [Controller] adds to [ControllerBase] everything related to views (methods [View], [ViewData], [TempData], etc.);
    • lines 12–15: the action generates the view template: a title, a message, and the current time;
    • line 16: [View(model)] returns a [ViewResult]: the action no longer generates the response; instead, it designates a view and passes a template to it. If no view name is specified, the view with the same name as the action is used: [Index];
    • lines 23–26: When the view depends on the request, the action selects the view. Here, the name [unknown] displays the view [Unknown], with status code 404. The template for this view is a simple string;
    • line 32: the action [Hello] explicitly specifies the view [Index] by name: two actions share the same view, with different templates.

    Where does [ASP.NET Core] look for the view [Index] for action [ViewsController.Index]? By convention, in two folders, in this order:

    • [Views/Views/Index.cshtml]: the folder named after the controller (without the suffix [Controller]);
    • [Views/Shared/Index.cshtml]: the folder containing views shared by all controllers (see Example 15).

    Let’s comment on this code:

    • Lines 2–5: A block of code named [@{ ... }] contains instructions named [C#]. It does not produce anything on the page. The variables it declares ([total], [count]) can be used later in the view;
    • line 16: a value [null] ([@Model.Nickname]) displays nothing, with no error;
    • Lines 18–19: An expression [@...] escapes the special characters in HTML ([<] becomes [&lt;]...): the text is displayed as-is. [@Html.Raw(...)] inserts it without escaping: it is interpreted as HTML. [Html.Raw] is used only for HTML generated by the application, never for data entered by a user: the user could inject HTML, or even [JavaScript], into the page (an attack known as [XSS], [cross-site scripting]);
    • Lines 21–27: a condition. After [@if (...)], the content within the curly braces is HTML: [Razor] recognizes the start of a tag and reverts to HTML mode. We return to [C#] via [@];
    • lines 32–40: a loop from [for] to [C#]. [var product = ...] is an instruction [C#], [<li>] of HTML: [Razor] alternates between the two without any specific marker;
    • Line 36: an explicit expression [@( ... )]. Parentheses are required whenever the expression contains spaces or operators (in this case, the conditional operator [? :]);
    • line 37: To write unformatted text within a [C#] block, enclose it in the special tag [<text>], which does not appear on the page;
    • line 38: [@:] does the same thing for the rest of the line;
    • lines 45–51: An empty list is simply [if]. In the [else] block, already in [C#] mode, [foreach] is written without [@];
    • line 55: the variables of the [@{ }] block and explicit expressions, including a method call: [ToString("0.00")] formats a number with two decimal places;
    • line 56: a pointed path [@Model.Address.Street], and a method call [ToUpper()];
    • line 57: [Razor] recognizes that a [@] placed between two alphanumeric characters is not code: [contact@example.com] is an email address. To write a [@] that would be ambiguous, we duplicate it: [@@].

    • line 14: a middleware component (see Chapter 7) that serves files from the [wwwroot] folder of the project: the file [wwwroot/css/styles.css] is served to URL and [/css/styles.css]. If the file does not exist, the request continues on to the controllers;

[PhysicalFileProvider] refers to a folder on the disk; [ContentRootPath] is the project folder. // ordinary C# functions, callable from the views: @Formats.Money(...)
public static class Formats

    public static string Uppercase(string? text) => (text ?? "").ToUpperInvariant();

    // an amount in a currency, in the format of the current language (CultureInfo.CurrentCulture)
    // "C" = currency; the NumberFormatInfo object sets the currency symbol
    public static string Money(decimal amount, string currency = "EUR")
    {
        var format = (NumberFormatInfo)CultureInfo.CurrentCulture.NumberFormat.Clone();
        format.CurrencySymbol = currency == "USD" ? "$" : "€";
        return amount.ToString("C", format);
    }

    // a date in full words, in the current language: "Wednesday, September 23, 2026"
    public static string Date(DateTime when) => when.ToString("D", CultureInfo.CurrentCulture);

    // a helper that builds HTML: it returns an IHtmlContent, which Razor does not escape.
    // It is then up to the helper to escape the data it inserts (HtmlEncoder)
    public static IHtmlContent Badge(int stock)
    {
        var cssClass = stock > 0 ? "text-bg-success" : "text-bg-danger";
        var text = HtmlEncoder.Default.Encode(stock > 0 ? $"{stock} in stock" : "sold out");
        return new HtmlString($"<span class=\"badge {cssClass}\">{text}</span>");
    }
}

    4.7.1. Validation by the browser

    The attributes [required], [maxlength], [min], [max], [type="email"]... instruct the browser to validate the form before submitting it: the user is immediately notified via a tooltip, without any round-trip communication with the server. This is the behavior achieved by clicking the “enable it” link (http://localhost:5000/register?html5=true), which removes the [novalidate] attribute from the form.

    This validation is a convenience, not a security measure: you can bypass it simply by removing the [required] attribute using the browser’s developer tools, or by sending the request with [curl]. Server-side validation remains essential. That’s why the example disables browser validation by default: to demonstrate how the server works. The case study, however, retains both: the HTML5 attribute for convenience, and server-side validation for security.

    4.8. Example 20: The Post/Redirect/Get Pattern

    When a POST form submits successfully, the action can display a page directly. The problem arises if the user then refreshes that page (F5 key): the browser resubmits the form, and the operation is performed a second time (an order placed twice, an appointment made twice...). The Post / Redirect / Get pattern (PRG) prevents this problem: a successful POST action does not generate a page; instead, it redirects to a GET page. Reloading this page simply triggers another GET, with no effect.

    One detail remains: the GET page must display a message (“the task has been added”), even though this message was generated by the POST action in a different request. To address this, [ASP.NET Core] provides [TempData]: a dictionary whose contents persist until the next request and disappear as soon as they are read. It is a flash message. By default, [TempData] is stored in a cookie, encrypted by the server.

    4.9. Example 21: Links, Buttons, and Confirmation

    A simple rule guides the choice between a link and a button:

    • a link ([<a href>]) generates a GET request. A GET request must not modify anything: browsers, search engines, and antivirus programs may follow links on their own to prepare or analyze a page;
    • an operation that modifies data (add, edit, delete, log out) is a button in a form POST.

    namespace Example21.Services;

// a contact: an identifier, a name, a phone number
public record Contact(int Id, string Name, string Phone);

// the contacts, in memory, shared by everyone (singleton)
public class ContactsService
{
    private readonly List<Contact> contacts =
    [
        new(1, "Marie Durand", "01 23 45 67 89"),
        new(2, "Paul Martin", "06 12 34 56 78"),
        new(3, "Philippe Jandot", "02 98 76 54 32"),
    ];
    private int lastId = 3;

    public IReadOnlyList<Contact> List() => contacts;

    // null if the contact does not exist
    public Contact? Read(int id) => contacts.Find(c => c.Id == id);

    public Contact? Edit(int id, string name, string phone)
    {
        var index = contacts.FindIndex(c => c.Id == id);
        if (index < 0) return null;
        // a record is immutable: we replace it with a modified copy (with)
        contacts[index] = contacts[index] with { Name = name, Phone = phone };
        return contacts[index];
    }

    public Contact Add(string name, string phone)
    {
        var contact = new Contact(++lastId, name, phone);
        contacts.Add(contact);
        return contact;
    }

    public Contact? Delete(int id)
    {
        var contact = Read(id);
        if (contact is not null) contacts.Remove(contact);
        return contact;
    }
}

    // confirmation of the forms that carry the data-confirmation="..." attribute
// Without JavaScript, these forms are simply sent without confirmation.
(() => {
  const modal = document.getElementById('confirmation-modal');
  const message = document.getElementById('confirmation-modal-message');
  let pending = null; // the form to send if the user confirms

  // 1. we intercept the submission of the forms to confirm
  document.querySelectorAll('form[data-confirmation]').forEach((form) => {
    form.addEventListener('submit', (event) => {
      event.preventDefault(); // the submission is suspended
      pending = form;
      message.textContent = form.dataset.confirmation;
      modal.classList.remove('d-none'); // the window appears
    });
  });

  // 2. the two buttons of the window
  modal.addEventListener('click', (event) => {
    const action = event.target.dataset.action;
    if (action === 'yes') {
      pending.submit(); // submission, WITHOUT firing the 'submit' event again
    } else if (action === 'no') {
      modal.classList.add('d-none');
      pending = null;
    }
  });
})();
    • line 3: the code is wrapped in a function that executes immediately, to avoid creating global variables;
    • lines 9–14: the submission of each form bearing the attribute [data-confirmation] is intercepted. [preventDefault()] suspends the submission; the form is stored, the question is placed in the window ([textContent], not [innerHTML]: the question is displayed as text, never interpreted as HTML), and the window is displayed;
    • Lines 19–25: “Yes” submits the cached form. The [submit()] method of a form submits it without triggering the [submit] event: there is no new confirmation prompt. “No” hides the window.

    If [JavaScript] is disabled, the forms simply submit without confirmation: the application still works. This is the principle of incremental improvement: [JavaScript] adds convenience, but it is not essential.
